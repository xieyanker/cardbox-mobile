# CardBox 3.0 需求记录

记录日期：2026-10-11。当前开发基线：用户已验收的 CardBox `2.0.0`。

状态：六项需求的代码与自动检查已完成，版本 `3.0.0`，Android 构建编号 5；真机与安装包验收待完成。用户于 2026-10-11 授权开始全部需求，要求图标优先、从简单到复杂、备份性能与密码校验最后处理，中途自主决定，不提问。开发直接在 `main` 上进行；四个功能阶段分别保存、提交并推送，方便额度中断后接续。标签 `3.0.0` 标记本轮代码版本，自动检查与真机验收的范围分别记录。

## 1. 重新设计应用图标

- 根据 CardBox 的本地卡片管理 / 卡包功能重新设计，风格简洁、美观。
- 图标设计中必须包含完整的 **CardBox** 字母。
- 其他元素、配色与构图由开发时自主设计，用户未指定额外限制。
- 后续执行时生成并接入实际应用图标。

## 2. 调整添加卡片入口

- 去掉首页现有的添加卡片加号按钮。
- 将“添加卡片”放入右上角第一个菜单（一级菜单），并作为第一条菜单项。
- 点击后进入现有添加卡片流程。

## 3. 简化备份管理菜单外观

- 去掉“备份管理”后用于提示存在子菜单的提示符。
- 保留备份管理的子菜单及其导入 / 导出功能。
- 用户直接点击“备份管理”后打开子菜单，无需额外提示符。

## 4. 优化备份导入、导出性能

- 用户反馈：文件内容不大，但导入、导出仍需要好几分钟，体验较差。
- 后续开发必须排查实际耗时原因并显著改善完成速度，不能仅调整加载提示或动画。
- 开发时记录优化前后的导入 / 导出耗时，并在 Android 真机上验证实际效果。
- 当前仅记录现象，尚未确定瓶颈；具体性能目标在测量基线后确定。
- 优化应保持备份数据完整、加密保护及已有备份格式的读取兼容性。

## 5. 导入密码错误时尽早提示

- 用户反馈：密码输入错误时，当前要等待很久才提示错误。
- 在导入流程尽可能早的阶段校验密码，发现错误后尽快提示并停止后续导入操作。
- 错误密码不应进入耗时的卡片 / 图片恢复流程，也不应改动现有卡包。
- 与第 4 项一起排查与优化，验证正确密码导入和错误密码提示各自的耗时。
- 用户认为可能与导入 / 导出慢有关；该关联尚未经过验证。

## 6. 增加卡片浏览模式

- 保留现有基础浏览方式：
  - 首页左右滑动浏览。
  - 卡片管理菜单中的平铺浏览。
- 新增三种浏览模式：**堆叠、聚焦、钱包**。
- 参考用户提到的 **arkflow** 应用的卡片展示效果，支持上下滑动，并提升切换与动画的流畅度。
- 后续开发时确定三种模式各自的布局、手势及模式切换入口；本次不预设尚未确认的具体界面。
- 验收时同时确认原有浏览方式可用，以及新增模式的上下滑动、选卡与动画体验。
